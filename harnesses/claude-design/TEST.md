# Test contract

Run core tests with `pytest -q harnesses/claude-design/tests/test_claude_design.py` and subprocess E2E contract tests with `pytest -q harnesses/claude-design/tests/test_full_e2e.py`.

Coverage includes stable envelopes; browser-first onboarding/auth readiness; minimal human-only authentication; no mandatory MCP registration/OAuth/setup token; optional MCP diagnostics; Claude Code 2.1.229 redirect URI defect; `Connected` not authorized; preserved 66-command parity (0.4.0 adds projects.qa.layout and projects.link.verify); exact short/long browser input routing; inert JSON encoding of quotes, newlines, Unicode, and markup; fail-closed evaluate-disabled behavior; exact readback verification; stale-ref and timeout diagnosis without automatic Gateway restart; exact preview/apply digests; project, design-system, template, code-sync, destination, and admin browser handoffs; exact-name deletion; identifier rejection; exact active-file identity; native PDF route discovery; foreground continuity after tool failures; expected full-deck and print-preview page counts; artifact metadata; explicit native/fallback provenance; page-by-page visual QA; Gateway-supported manifest schemas; metadata and manifest contracts; and secret-literal exclusion.

The E2E contract inventory covers A, recovered exact 14-slide route; B, provider failure only after two bounded fresh-list attempts against the same generated-result thumbnail; C, Browser/CDP failure never classified as provider failure; D, exact thumbnail identity among multiple results; and E, recovered route followed by independent PPTX/PDF 14/14 export-verification gates. It also covers invalid input, missing evidence, ambiguity, repeated invocation/idempotency, and secret redaction.

No live credentials, provider mutation, publication, MCP registration, OAuth attempt, browser action, or fabricated export occurs in tests. The Harness plans and verifies supplied evidence only. Registry sync, repository validation, Gateway-schema compatibility, and a repository secret scan are separate release checks.
