# ClawPod Node Host

Use the linked `clawpod-node-host` Harness through `cli_harness`. Follow these eight stages for a new computer connection. Reuse verified completed stages; resume at the first unfinished stage. The Node app does not install Tailscale.

1. **Agent Tailscale sign-in.** Run `agent.status`. If it reports `NeedsLogin`, run `agent.login`, send the returned sign-in link to the user, and recheck `agent.status` after they sign in. Continue only when it reports `Running`. Keep an already connected agent unchanged. A returned login link is not proof of sign-in.
2. **Computer Tailscale installation and sign-in.** Help the user install Tailscale from [the official download page](https://tailscale.com/download) if missing and sign in to the same intended tailnet on their computer. Verify both devices can communicate. Do not confuse the computer's login with the agent's login. Ask only for missing platform information needed at this stage; reuse it below.
3. **Confirm the user's computer.** Establish the user's target computer OS and CPU from conversation or target evidence, not the agent pod. Supported Node packages are Linux x64 (Debian/Ubuntu desktop), macOS arm64 (Apple Silicon) or x64 (Intel), and Windows x64.
4. **Select the installer.** Run `installer.info` with `platform` and `arch`. Give the matching download link and checksum. This lookup is offline and does not perform the preceding sign-ins. Use the selected artifact’s signing and notarization status from the release metadata; Windows publisher signing is not included. Consult the release validation scope for the tested platforms. State the relevant limitation once.
5. **Save and deliver connection values.** Verify the active Gateway token (or password), its Tailscale address, and full WebSocket endpoint. Find the matching Gateway secret in the catalog or with `memory_secret_search`; create it with `memory_secret` if missing. If the active value changed, use `memory_secret_update` on the existing pointer; reuse a verified unchanged value. The main agent must send the actual credential to the requesting user's room with `room_send.useSecrets`: put a placeholder in `content` and pass `{ name: pointerId, placeholder }`. The runtime inserts the value into the delivered room message. A pointer ID, masked value, or “saved in Secrets” notice alone does not complete delivery. Keep the endpoint and credential in separate labeled fields and confirm the send succeeded. Follow [onboarding](references/onboarding.md) for active-source verification, exact tool arguments, and rotation handling.
6. **Install and start ClawPod Node.** For a plain Gateway listener, supply `ws://<Tailscale-IP>:<port>`; private/Tailscale IP connections need no enable option. Use `wss://` only when that endpoint provides TLS. Have the user install the DEB/PKG/EXE, open ClawPod Node to show its setup page in the default browser, enter the URL, display name, and actual token/password in separate fields, then select **Save settings → Start node**. Node.js, the node runtime, and desktop components are bundled. Check **Desktop setup**: macOS requires permissions for **ClawPod Node**, Windows requires an interactive desktop, and Linux requires an available X11 or Wayland session. See [onboarding](references/onboarding.md) for OS-specific steps. Desktop permission is separate from Gateway pairing; missing GUI permission does not prevent CLI connection setup.
7. **Approve and verify the device.** Inspect actual pending device requests using the available Gateway device-pairing tools. Match the user's computer by its real device/request identity, approve that exact request within the connection task, then verify that exact node is connected. A display name alone is not an identity; resolve ambiguity before approval. Local app **Running** only describes its process.
8. **Use the connection.** Find the connected Node ID with `nodes` (`action: "status"`). Use `remote_computer` with that `node` for its GUI, `exec` with `host: "node"` and `node` for commands, or `browser` with `target: "node"` and `node` for a compatible installed browser. Local `computer` still operates the agent pod. For background or interactive CLI work, use the returned `sessionId` with `process`; both the Agent and Node must support managed execution (`system.process`). Check advertised commands before using a feature; the Gateway Agent must also include `remote_computer`. For desktop work, follow [app operations](references/operations.md): status → acquire → act using the returned frame → release. Update both Node to 0.2.3 and the controlling Agent for monitor switching and stable observation coordinates; switch monitors with a fresh screenshot or observe using `display_id` and omitting `frame_id`, then use the new response’s `frameId` and viewport for inputs. An old monitor’s frame still produces `STALE_FRAME`. For a correctly configured node that still cannot connect or pair, use `node-connect` if available or report the specific diagnostic evidence.

The Harness commands are `agent.status`, `agent.login`, and `installer.info`. Do not generate node installation scripts, provision over SSH, or install a separate global CLI for this workflow. Device pairing is performed by the Gateway tools, not by a synthetic enrollment ID. Keep actual credentials out of URLs, public repository files, and diagnostic logs; the intended user receives the verified value separately.

If a stage cannot finish, explain the concrete missing action and resume that stage after it is resolved. Do not silently skip Tailscale setup or claim connectivity from login alone. Let the user complete their own browser sign-in and local OS prompts.

Use [app operations](references/operations.md) for Reconnect, Stop, startup, upgrades, and removal. The app's `.clawpod-node` state is separate from existing `.openclaw` state. This capability does not administer tailnet policy or the Gateway lifecycle.
